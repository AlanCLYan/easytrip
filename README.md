# easytrip 旅遊行程

和旅伴一起規劃旅行的網站，每個人用自己的密碼登入，誰新增、修改了什麼都有紀錄。

- 📅 **每日行程**：依天數排列，時間自動排序，地點一鍵開 Google 地圖；旅行期間自動打開當天
- 🏨 **住宿交通**：航班、飯店、車票、租車、票券的訂位代號（點一下複製）、時間與地址
- ✅ **行前清單**：打包清單和出發前待辦，顯示完成進度和是誰勾的
- 📴 **離線查看**：看過的資料會存在手機裡，在國外沒網路也能看

網址：https://alanclyan.github.io/easytrip/

## 一、整體架構

```
┌──────────────────────┐   讀寫（每次都附密碼）   ┌───────────────────────────┐
│ 網站（GitHub Pages）  │ ◀────────────────────▶ │ Google 試算表「easytrip 資料庫」│
│ index.html + js/     │                        │ 透過 Apps Script 存取        │
└──────────────────────┘                        └───────────────────────────┘
  手機、電腦都能用                                users / trips / items / bookings
  看過的資料會暫存在裝置裡                          checklist / expenses / log
```

| 角色 | 放在哪裡 | 費用 |
|---|---|---|
| 網站 | GitHub Pages（這個儲存庫） | 免費 |
| 資料庫 | Google 試算表「easytrip 資料庫」＋ Apps Script | 免費 |

和 superWeb 不同：這個網站**讀取也需要密碼**，而且目前不需要 GitHub Actions 排程。


## 三、用戶與權限

### 新增旅伴

打開試算表的 `users` 工作表，新增一列：

| 欄位 | 填什麼 |
|---|---|
| `id` | 英文代號，例如 `amy`。只能用英文、數字、`-`、`_`；**建立後不要改**（旅行成員是用 id 記錄的） |
| `name` | 顯示名稱，例如 `小美` |
| `key` | 這個人的密碼，8 碼以上、每人不同 |
| `role` | `admin`、`editor` 或 `viewer` |
| `note` | 備註，隨意 |

填完後到 Apps Script 執行一次 **checkUsers**，確認沒有填錯。新增用戶**不需要重新部署**，立刻生效。

把網址和密碼傳給對方，對方登入後，再到旅行的「✏️ 編輯」把他勾選為成員。

### 角色

| 角色 | 能看的旅行 | 能做的事 |
|---|---|---|
| `admin` | 全部 | 所有操作 |
| `editor` | 自己是成員的旅行 | 新增、修改、刪除行程內容；可以建立新旅行 |
| `viewer` | 自己是成員的旅行 | 只能看 |

- 旅行的**成員名單**和**刪除旅行**，只有該旅行的建立者或 admin 能做
- 停用某人：把 `role` 改成任何其他文字（例如 `停用`）
- 換密碼：直接改 `key`，對方下次操作時會被要求重新登入
- 密碼 10 分鐘內錯 20 次，所有人會暫停登入 10 分鐘

> ⚠️ 密碼直接存在試算表裡，**試算表不要分享給任何人**。旅伴只需要網址和自己的密碼。

### 操作紀錄

- 每筆資料都有 `createdBy`／`createdAt`（誰、何時建立）與 `updatedBy`／`updatedAt`（誰、何時最後修改），網站上也會顯示「小美 修改・3 小時前」
- `log` 工作表逐筆記錄每一次新增、修改、刪除的時間、用戶、工作表、資料 id 和內容；刪除的資料內容也會留在這裡，誤刪時可以從這裡找回

## 四、新增一個分頁

範本 `js/tabs/_template.js` 是一個完整可用的分頁，可以照著改。

### 步驟 1：需要新的工作表時（沿用現有資料可跳過）

打開試算表 → **擴充功能 → Apps Script**：

```js
const SCHEMA = {
  // ...原本的不要動...
  memos: ['id', 'tripId', 'text', ...AUDIT]   // ← 新增；第一欄一定是 id，第二欄是 tripId
};
const NUMBER_FIELDS = ['day', 'amount'];       // 數字欄位加在這裡
const TRIP_CHILDREN = ['items', 'bookings', 'checklist', 'expenses', 'memos'];   // ← 加上新工作表
```

- 已經有資料的工作表也可以加欄位：程式是依欄位名稱讀取的，setup 會把新欄位補在工作表最右邊，舊資料不會錯位
- 儲存 → 函式選 **setup** → ▶ 執行
- **部署 → 管理部署作業 → ✏️ 編輯 → 版本選「新版本」→ 部署**（網址不變）

### 步驟 2：建立分頁檔

複製 `_template.js`，改名為例如 `js/tabs/memo.js`，修改標 ★ 的地方。`render(root, ctx)` 裡可以用：

| 寫法 | 用途 |
|---|---|
| `ctx.trip` | 這趟旅行（name、startDate、endDate、members…） |
| `ctx.data.memos` | 這趟旅行在某個工作表的所有資料（陣列） |
| `ctx.canEdit` | 目前用戶能不能修改（viewer 或離線時是 false） |
| `await ctx.add('memos', {...})` | 新增，tripId 會自動帶入 |
| `await ctx.update('memos', id, {...})` | 修改 |
| `await ctx.remove('memos', id)` | 刪除 |
| `ctx.rerender()` | 重畫這個分頁 |
| `ctx.meta(row)` | 「群倫 新增・3 小時前」 |
| `UI.esc(文字)` | 顯示資料前一定要用 |
| `UI.form({...})` | 跳出表單視窗（用法寫在 ui.js） |
| `UI.toast('訊息')` | 底部提示 |
| `UI.mapUrl(地點)` | Google 地圖連結 |

### 步驟 3：加進網站

在 `index.html` 的分頁區加一行，順序就是分頁的順序：

```html
<script src="js/tabs/checklist.js"></script>
<script src="js/tabs/memo.js"></script>   <!-- ← 新增 -->
```

## 五、日常維護

| 情況 | 怎麼做 |
|---|---|
| 新增旅伴 | 見「三、用戶與權限」，不用重新部署 |
| 上傳新版網站 | GitHub → **Add file → Upload files**，把檔案拖進去，同名檔案會直接覆蓋 → Commit changes |
| 修改 Apps Script 後網站沒變 | 一定要「部署 → 管理部署作業 → 編輯 → 新版本」 |
| 上傳後網站沒變 | 等 1～2 分鐘，用無痕視窗或強制重新整理（Mac：Cmd+Shift+R） |
| 看不到旅伴剛改的內容 | 旅行頁面按「🔄 重新整理」 |
| 換了一台裝置 | 重新輸入一次密碼即可 |

## 六、疑難排解

- **登入時顯示「密碼不正確或帳號已停用」**：檢查 `users` 的 `key` 有沒有多打空白、`role` 是否為 admin／editor／viewer；執行 **checkUsers** 檢查
- **顯示「密碼錯誤次數過多」**：等 10 分鐘
- **顯示「伺服器回應格式錯誤」**：Apps Script 部署時「誰可以存取」要選「所有人」，「執行身分」選「我」
- **顯示「連不上伺服器」**：確認網路；沒網路時仍可看之前載入過的旅行
- **旅伴看不到旅行**：到旅行的「✏️ 編輯」把他勾選為成員
- **日期或時間在試算表裡變成奇怪的格式**：執行一次 **setup**，會把所有欄位重設為純文字
